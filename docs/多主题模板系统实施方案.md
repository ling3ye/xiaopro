# 构建时多主题模板系统实施方案

> 站点：https://lingflux.com
> 框架：Astro 7.2.0（多语言 i18n，9 种语言，约 860 页）
> 制定日期：2026-08-11
> 状态：已评审修正，待执行
> 方案来源：用户原始方案 + 代码实地核查修正（关键修正见第二节）

---

## 一、目标与原则

- 每套主题一个独立文件夹（`src/themes/<name>/`），皮肤层和结构层完全自主、互不影响
- 通过配置文件切换默认主题，整站重新构建生效
- **不做运行时用户切换**（主题 2 未完成，避免体验问题）
- 当前深色主题作为 `dark` **冻结不动**（原封搬迁）；新主题 `ocean` 做试验田（更好的响应式、代码阅读/复制体验）
- 内容（`src/content/`）、内容配置（`src/content.config.ts`）、i18n、utils 一律不动

---

## 二、关键修正：为什么不能用"代理组件静态 import 全部主题"

原方案的 `DefaultLayout.astro` 静态 import 所有主题再用 `layoutMap` 选择：

```astro
import DarkLayout from '../themes/dark/Layout.astro';
import OceanLayout from '../themes/ocean/Layout.astro';  // ← 问题根源
```

**这是不可行的。** Astro/Vite 按**静态模块图**收集 CSS，与运行时是否渲染无关：只要 `import OceanLayout` 存在（即使从未被渲染），`ocean/global.css` 就会打进每个页面的产物。两套主题的 `:root` 变量块互相覆盖，谁生效取决于打包顺序 —— ocean 上线之日就是 dark 被污染之时。

原方案注意事项第 6 条"构建时只有一个主题被引入，不存在变量冲突"的假设**不成立**。

### 修正方案：Vite 别名 `@theme` 实现真·单主题构建

模块图中物理上只存在一套主题，杜绝 CSS 串扰，同时保留"改一个值 → 重新构建"的切换体验：

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import { fileURLToPath } from 'node:url';
import sitemap from '@astrojs/sitemap';
import { defaultTheme } from './src/theme.config.ts';  // config 加载器支持 import TS

export default defineConfig({
  site: 'https://lingflux.com/',
  vite: {
    resolve: {
      alias: {
        '@theme': fileURLToPath(new URL(`./src/themes/${defaultTheme}`, import.meta.url)),
      },
    },
  },
  integrations: [ /* sitemap 配置保持不变 */ ],
});
```

```astro
---
// src/layouts/DefaultLayout.astro — 构建时主题入口（模块图中永远只有一套主题）
import ActiveLayout from '@theme/Layout.astro';
---

<ActiveLayout {...Astro.props}>
  <slot />
</ActiveLayout>
```

```jsonc
// tsconfig.json — 让编辑器识别别名（IntelliSense 固定指向 dark，仅影响编辑器，不影响构建）
{
  "extends": "astro/tsconfigs/strict",
  "include": [".astro/types.d.ts", "**/*"],
  "exclude": ["dist"],
  "compilerOptions": {
    "paths": { "@theme/*": ["./src/themes/dark/*"] }
  }
}
```

**备选方案**（若坚持保留原代理组件）：两套主题的 global.css 都必须改用作用域选择器（`html[data-theme='dark']` / `html[data-theme='ocean']`），且各主题 Layout 的 `<html>` 标签上设置对应 `data-theme`。脆弱且浪费字节，不推荐。

## 三、实地核查确认的事实（2026-08-11 核查）

| 核查项 | 结果 |
| --- | --- |
| 引用 Layout 的页面数 | **24 个文件**，三种相对深度（`../../`、`../../../`、`../../../../`），均以 `layouts/Layout.astro` 结尾 —— 只改文件名的批量替换可行 |
| `global.css` 引用方 | **仅 `Layout.astro`**；593 行，无 `url()`/`@import`/`@font-face`，搬迁无资源路径问题 |
| Layout 插槽 | 仅默认 `<slot />`，无具名插槽，代理转发简单 |
| Header/Footer 引用方 | 仅 `Layout.astro`，无页面级直接引用 |
| `Sidebar.astro` | **死代码**，全项目无人引用 —— 不搬迁（留共享层或删除） |
| `Welcome.astro` | Astro 脚手架残留死代码（引用 `../assets/astro.svg`），顺带清理 |
| Shiki 配置 | `astro.config.mjs` 无 markdown 配置，用 Astro 默认主题 |
| 页面目录 Markdown | `src/pages/` 下无 `.md`，全部内容走 Content Layer API，不受主题迁移影响 |

## 四、目标目录结构

```
src/
  themes/
    dark/                           # 主题 1：当前深色主题（原封搬迁，冻结）
      Layout.astro                  # 从 src/layouts/Layout.astro 复制 + 调整 import
      global.css                    # 从 src/styles/global.css 原样复制
      components/
        Header.astro                # 从 src/components/Header.astro 复制 + 调整 import
        Footer.astro                # 从 src/components/Footer.astro 复制 + 调整 import
    ocean/                          # 主题 2：全新主题（后续从空白开发）
      Layout.astro
      global.css
      components/
        Header.astro
        Footer.astro
  theme.config.ts                   # export const defaultTheme = 'dark'
  layouts/
    DefaultLayout.astro             # 唯一入口：import '@theme/Layout.astro'
  components/                       # 共享组件（Card、Breadcrumb、Pagination、
                                    #   CompareWidget、Tag、AffiliateLink 等，用 CSS 变量）
  pages/                            # 24 个页面的 import 改为 layouts/DefaultLayout.astro
  styles/                           # 迁移完成并验证后删除
  content/  content.config.ts  i18n/  utils/   # 一律不动
```

### 主题独有 vs 共享组件

- **主题独有**（每套主题各自一份）：`Layout`、`Header`、`Footer`
- **共享**（留在 `src/components/`，用 `var(--color-primary)` 等变量自动适配各主题）：`Card`、`Breadcrumb`、`Pagination`、`CompareWidget`、`Tag`、`AffiliateLink`
- 硬编码颜色（约 70 处，多为 gradient 和 badge 背景）本次不动，ocean 迭代时逐步收敛到变量

## 五、import 路径调整清单（复制到 themes/dark/ 时）

**`themes/dark/Layout.astro`（4 处）**：

| 原（`src/layouts/Layout.astro`） | 改为 |
| --- | --- |
| `import '../styles/global.css'` | `import './global.css'` |
| `import Header from '../components/Header.astro'` | `import Header from './components/Header.astro'` |
| `import Footer from '../components/Footer.astro'` | `import Footer from './components/Footer.astro'` |
| `from '../i18n/config'` | `from '../../i18n/config'` |

**`themes/dark/components/Header.astro`（1 处）**：`from '../utils/i18n'` → `from '../../utils/i18n'`

**`themes/dark/components/Footer.astro`（2 处）**：`from '../utils/i18n'` → `from '../../utils/i18n'`；`from '../i18n/config'` → `from '../../i18n/config'`

> ⚠️ 注意相对深度：`themes/dark/X.astro` → `src/` 是 `../../`；`themes/dark/components/X.astro` → `src/` 是 `../../../`。原方案示例中 Layout 引用共享组件写 `../../../components/` 是笔误，应为 `../../components/`（当前 Layout 实际不引用共享组件，页面引用共享组件的路径不变，因为页面不移动）。

`theme.config.ts` 内容：

```typescript
// src/theme.config.ts
// 切换默认主题只需改这一个值，整个站点重新构建即可
// 同时被 astro.config.mjs（Vite 别名）和 DefaultLayout.astro 引用
export const defaultTheme = 'dark';

export const availableThemes = ['dark'] as const;
export type ThemeId = (typeof availableThemes)[number];
```

## 六、代码高亮（Shiki）

- **本期**：保持 Astro 默认 Shiki 主题不动
- **ocean 成熟时**：`astro.config.mjs` 读同一个 `defaultTheme` 值切换，几行即可：

```js
markdown: {
  shikiConfig: { theme: defaultTheme === 'ocean' ? 'github-light' : 'github-dark' },
},
```

## 七、实施步骤（执行任务要点）

1. **开分支**：`git checkout -b feat/multi-theme`，确保工作区干净
2. **创建结构**：`src/themes/dark/components/`、`src/theme.config.ts`
3. **搬迁 dark 主题**：
   - 复制 `src/layouts/Layout.astro` → `src/themes/dark/Layout.astro`，按第五节调整 4 处 import
   - 复制 `src/styles/global.css` → `src/themes/dark/global.css`（原样，不改内容）
   - 复制 `Header.astro`、`Footer.astro` → `src/themes/dark/components/`，各调整 1/2 处 import
4. **接线**：`astro.config.mjs` 加 `@theme` 别名；新建 `src/layouts/DefaultLayout.astro`；`tsconfig.json` 加 paths
5. **批量改页面 import**（24 个文件，macOS 命令）：

   ```bash
   cd src/pages && grep -rl "layouts/Layout\.astro" . | xargs sed -i '' "s|layouts/Layout\.astro|layouts/DefaultLayout.astro|g"
   ```

6. **构建验证**：`pnpm run build`，确认 860 页全量通过（在 /tmp 目录构建可绕过沙箱删除保护，参考 Astro 7 升级记录）
7. **验证通过后**删除旧文件：`src/layouts/Layout.astro`、`src/styles/`（死代码 Sidebar/Welcome 另行清理）
8. **提交**：单独一个 commit，便于回滚
9. **ocean 开发**：按需创建 `src/themes/ocean/`（可先做占位 Layout 验证切换链路，见验证清单）

## 十、注意事项

- **不要改** `src/content/`、`src/content.config.ts`、页面核心逻辑（只动一行 import）
- 不引入任何客户端 JS 主题切换，纯构建时静态切换
- 每个主题的 `global.css` 用 `:root` 定义完整变量块即可（别名方案保证构建产物只有一套主题，无冲突）—— 这是别名方案相对原代理方案的核心收益
- `theme.config.ts` 被 `.astro` 或 `astro.config.mjs` import 均无 tree-shaking 风险（字符串常量），原方案的相关顾虑不成立
- 切换主题后**必须重启 dev server**（Vite 别名在启动时解析）
